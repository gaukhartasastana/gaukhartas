## ✅ Архитектура: админка подключена к сайту (вариант A)

**Было:** `index.html` не подключал ни `engine.js`, ни `content.js`. Админка писала
в `localStorage['gh_content']`, который никто не читал. Менеджер менял цену —
на сайте оставалась старая, захардкоженная в разметке.

**Стало:** подключён слой данных. Цены, вместимость залов, телефоны, адрес и часы
работы берутся из `content.js` и переопределяются админкой.

Реализовано **привязкой данных**, а не блочным рендерингом: движок рисует своими
классами `gh-*` под `base.css` — если бы мы включили `data-block=…`, фирменная вёрстка
этой страницы (кожаная книга меню, интро, галерея) была бы затёрта. Поэтому
`base.css` намеренно **не подключён**, а к существующим элементам проставлены
атрибуты `data-gh="путь"`.

### Что теперь редактируется через админку

| Элемент на сайте | Привязка |
|---|---|
| Цены трёх пакетов | `menus.0.price`, `menus.1.price`, `menus.2.price` |
| «от 13 500 ₸» в блоке цифр | `menus.0.price` |
| Вместимость залов (подпись на фото и в характеристиках) | `halls.0.min/max`, `halls.1.min/max` |
| Названия залов | `halls.0.name`, `halls.1.name` |
| Телефон (3 места + `tel:` ссылки) | `contacts.phone1`, `data-gh-href="tel1"` |
| Все ссылки WhatsApp | `data-gh-href="wa"` |
| Адрес и город | `contacts.address`, `contacts.city` |
| Часы работы | `contacts.hours`, `contacts.hoursShort` |

Плюс движок теперь генерирует `<title>`, meta-описание, Open Graph и микроразметку
Schema.org (`EventVenue` + `FAQPage`) из тех же данных, и ведёт аналитику кликов.

### Как добавить новую привязку

```html
<!-- текст -->
<span data-gh="contacts.phone2">+7 775 828 17 55</span>

<!-- сумма: отформатируется как «15 500 ₸» -->
<span data-gh="menus.1.price" data-money>15 500 ₸</span>

<!-- ссылка -->
<a href="tel:+77760077725" data-gh-href="tel1">Позвонить</a>
```

Путь — это адрес поля в `content.js`. Проверено: битые данные из админки
(`halls: []`, `menus: null`, цена строкой, сломанный JSON) сайт не роняют —
подставляются значения по умолчанию.

### ⚠️ Расхождение в данных — нужно подтверждение

`content.js` и живая страница показывали **разные цифры**:

## 🚀 Хостинг: Render + Spaceship

Добавлен `deploy/render.yaml` и настроено кэширование в `server.js`
(картинки на год, HTML всегда свежий).

**Важно про бесплатный план Render:** Web Service засыпает после 15 минут
простоя. Первый заход после сна — **около 50 секунд белого экрана**.
Для лендинга, куда приходят из поиска и с рекламы, это критично: человек
уйдёт задолго до загрузки.

Варианты:

| | Плюсы | Минусы |
|---|---|---|
| **Render Static Site** (бесплатно) | Не засыпает, отдаётся с CDN, мгновенно | Админка не работает — нет `/api/*`. Контент правится в `content.js` руками |
| **Render Web Service + $7/мес** | Не спит, админка работает | Платно |
| **Static Site + внешняя админка** | Бесплатно и быстро | Правки через commit в репозиторий |

Рекомендация: **Static Site**, пока поток заявок не окупит $7. Сайт-визитка
не должна ждать 50 секунд.

### Настройка домена на Spaceship

В панели Spaceship → DNS для `gaukhartas.com`:

```
Тип     Хост    Значение
A       @       216.24.57.1
CNAME   www     gaukhartas.onrender.com
```

В Render → Settings → Custom Domain добавить `gaukhartas.com` и `www.gaukhartas.com`.
SSL выпустится автоматически за 10–60 минут. DNS расходится до 24 часов.

Слово **«қаза» означает «смерть, кончина, утрата»**. В подвале сайта банкетного

# Итерация 4: вкладка «Репутация» в админке

## 🐛 Попутно найденный баг

Поле «Google Analytics 4» в админке было, но **код счётчика на сайт никогда
не вставлялся**. Вводишь `G-XXXXXXX` — и ничего не происходит, статистика
никуда не идёт. То же с Google Ads, TikTok и Meta Pixel.

Исправлено: `GH.analytics()` собирает и вставляет счётчики из настроек.
ID проверяются регулярками (`G-…`, `AW-…`, только цифры для Метрики) —
мусорная строка не попадёт в страницу. События сайта (клик в WhatsApp,
отправка формы, выбор меню) дублируются во все подключённые системы.

Добавлена **Яндекс.Метрика** — в Казахстане её данные полнее, чем у Google
Analytics, плюс карта кликов и запись сессий.

## 📊 Что можно и чего нельзя автоматизировать

Автоматически тянуть цифры из Google Business Profile и Яндекс Бизнеса
в админку **не получится**, и вот почему:

* **Google Business Profile API** требует отдельного проекта в Google Cloud,
  OAuth-авторизации и заявки на доступ, которую Google рассматривает неделями.
  Токены нельзя держать в клиентском JS — их увидит любой, кто откроет исходник.
* **Яндекс Бизнес** публичного API для статистики карточки не даёт вовсе.
* **2ГИС** тоже не отдаёт данные по отзывам наружу.

Поэтому вкладка сделана иначе: цифры вносятся руками раз в неделю (это две
минуты), а система считает, показывает динамику и говорит, что делать.
Прямые ссылки на все кабинеты — в один клик из админки.

## 🧮 Калькулятор отзывов

Формула: чтобы поднять средний рейтинг с `R` при `N` отзывах до цели `T`,
нужно `x ≥ N·(T−R) / (A−T)`, где `A` — средняя оценка новых отзывов.

Важная деталь: `A` считается не как 5,0, а с учётом реальной доли пятёрок.
Если пятёрок 85%, а остальные четвёрки, то `A = 4,85`. И тогда:

* цель 4,8 при 37 отзывах и 85% пятёрок → **297 отзывов**
* та же цель при 100% пятёрок → **74 отзыва**

Разница в четыре раза. Поэтому калькулятор честно предупреждает,
когда цель недостижима: при 80% пятёрок средняя новых отзывов 4,8 —
до 4,9 рейтинг не дойдёт никогда, сколько ни собирай.

Отдельное предупреждение про **5,0**: держать невозможно, одна четвёрка
при 100 отзывах роняет до 4,99. Реальная цель для банкетного зала — **4,8–4,9**.
Выше 4,9 клиенты начинают подозревать накрутку.

Ещё калькулятор показывает, насколько упадёт рейтинг от одного отзыва
на 1 звезду — при 37 отзывах это ощутимо, при 300 почти незаметно.
Это второй аргумент за объём, а не только за среднее.

Граничные случаи закрыты: буквы, отрицательные числа, рейтинг больше 5,
ноль отзывов (тогда цель — первые 10, раньше площадки рейтинг не показывают).
